# CosmoSats Advanced Production API

Полная документация по развертыванию и использованию бэкенда для расчета спутниковых группировок (проект КосмоХакатон 2026).

## 1. Установка и запуск

Сервер написан на Python с использованием FastAPI. Для корректной работы требуется активировать виртуальное окружение и установить зависимости:

**Для Linux/Ubuntu:**

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000

```

После успешного запуска интерактивная панель управления (Swagger UI) будет доступна в браузере по адресу: **[http://127.0.0.1:8000/docs](https://www.google.com/search?q=http://127.0.0.1:8000/docs)**

## 2. Рабочий процесс (Как пользоваться API)

Логика работы с бэкендом построена на последовательных шагах. Все действия выполняются через интерфейс Swagger:

1. **Загрузка базы (`POST /api/load`)**
Вставьте стартовый JSON-сценарий (обязательно с корневым ключом `"scenario_data"`). Это инициализирует систему. Без этого шага остальные методы вернут ошибку.
2. **Модификация конфигурации (`POST /api/update-config`)**
Изменяйте ключевые параметры "на лету" без перезагрузки всего файла. В случае передачи неверных данных сработает защита, и сервер вернет код `400` вместо падения.
*Пример запроса:*
```json
{
  "launch_stage": 3,
  "isl_range_km": 2000,
  "planes_update": [],
  "failures_update": []
}

```


3. **Сохранение эталонов (`POST /api/save-variant/{name}`)**
Обязательно сохраняйте удачные конфигурации перед экспериментами (например, под именем `stage3`). Бэкенд физически запишет настройки в папку `saved_variants/`, защитив их от потери при перезапуске сервера.
4. **Анализ и сравнение**
* **`GET /api/analysis`**: Запускает суточную симуляцию и возвращает отчет по доступности связи для каждого терминала.
* **`GET /api/compare/{name1}/{name2}`**: Принимает имена двух файлов из папки `saved_variants`, проводит расчет обоих вариантов и показывает математическую разницу метрик.


5. **Умные алгоритмы**
* **`GET /api/robustness`**: Поочередно отключает активные аппараты и выводит рейтинг спутников, потеря которых сильнее всего ударит по связи.
* **`GET /api/auto-tune`**: Автоматически подбирает лучшие углы наклона и фазирования плоскостей, используя комбинацию случайного поиска и локального спуска.


6. **Экспорт отчетов**
Используйте группу методов **`/api/export...`** для прямого скачивания результатов симуляции в виде готовых `.json` файлов на ваш компьютер (браузер сам предложит сохранить файл).

## 3. Структура исходного кода

* **`main.py`** — ядро приложения, описывающее REST-эндпоинты, валидацию запросов и логику безопасной работы с файловой системой.
* **`geometry.py`** — расчет баллистики, фильтрация видимости спутников по углам места и строгая валидация JSON-схем на входе.
* **`router.py`** — поиск кратчайшего пути передачи данных (алгоритм BFS) от клиента к шлюзу через активные межспутниковые линки.
* **`analyzer.py`** — пошаговый движок. Прогоняет сценарий по временной сетке, собирает статусы маршрутов и считает итоговый процент доступности сети.
* **`resilience.py`** — изолированный модуль стресс-тестирования группировки на отказоустойчивость.
* **`optimization.py`** — математический модуль поиска оптимальных параметров фазирования (RAAN и phase) в условиях ограниченного времени на вычисления.
* **`adapter.py`** — легковесный конвертер форматов данных между симулятором и аналитическими модулями.
