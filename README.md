# CosmoSats Advanced Production API

Вычислительный бэкенд для моделирования, анализа и оптимизации спутниковых группировок. Разработан в рамках проекта КосмоХакатон 2026.

Система позволяет загружать параметры орбитальных группировок, симулировать их движение в течение суток, строить динамические маршруты связи и проверять систему на устойчивость к отказам.

---

## 1. Архитектура и алгоритмы

Проект построен по модульному принципу. Каждый скрипт отвечает за строго определенную математическую или логическую задачу.

* **`main.py`** — Точка входа на базе FastAPI. Отвечает за маршрутизацию HTTP-запросов, валидацию JSON-схем, управление кэшем в оперативной памяти и безопасное сохранение конфигураций на жесткий диск.
* **`geometry.py`** — Баллистический калькулятор. Рассчитывает координаты спутников ($X, Y, Z$) в инерциальной и вращающейся системах координат. Вычисляет углы места (elevation) для наземных станций и дальность между аппаратами.
* **`router.py`** — Маршрутизатор. Использует алгоритм поиска в ширину (**BFS**) для нахождения кратчайшего пути от клиентского терминала до шлюза (gateway). Учитывает доступность межспутниковых линий (ISL) и статус наземных шлюзов.
* **`analyzer.py`** — Движок симуляции. Прогоняет расчеты по временной сетке (например, каждые 120 секунд на протяжении 86400 секунд). Фиксирует разрывы связи (outages) и считает суммарную доступность сети (availability).
* **`resilience.py`** — Модуль стресс-тестирования. Поочередно отключает активные спутники на весь период симуляции, чтобы составить рейтинг наиболее уязвимых узлов сети.
* **`optimization.py`** — Модуль автоподбора орбит. Комбинирует случайный поиск (Random Search) с локальным спуском (Coordinate Descent) для нахождения оптимальных углов наклона и фазирования, максимизирующих доступность связи для клиентов.
* **`adapter.py`** — Вспомогательный слой (паттерн Adapter) для преобразования тяжеловесных логов симуляции в компактные метрики для модулей аналитики.

## 2. Установка и запуск

Для работы требуется Python 3.10+.

### Настройка для Linux (Ubuntu)
```bash
# Создание и активация виртуального окружения
python3 -m venv venv
source venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt

# Запуск сервера
uvicorn main:app --reload --port 8000

```

### Настройка для Windows

```cmd
:: Создание и активация виртуального окружения
python -m venv venv
venv\Scripts\activate

:: Установка зависимостей
pip install -r requirements.txt

:: Запуск сервера
uvicorn main:app --reload --port 8000

```

Документация и панель управления (Swagger) доступны по адресу: **http://127.0.0.1:8000/docs**

## 3. Справочник API и рабочий процесс

### 3.1. Инициализация

**`POST /api/load`**
Загружает стартовый сценарий формата `cosmo-A-1.0`. Без этого шага система работать не будет.

* **Тело запроса:** Полный JSON-объект сценария, обернутый в ключ `scenario_data`.

### 3.2. Редактирование

**`POST /api/update-config`**
Позволяет точечно менять параметры активного сценария без перезагрузки базового файла.

* **Формат запроса:**

```json
{
  "launch_stage": 3,
  "isl_range_km": 2000.0,
  "planes_update": [
    { "id": "P1", "raan_deg": 15.0, "phase_deg": 0.0 }
  ],
  "failures_update": [
    { "satellite_id": "S14", "start_s": 21600, "end_s": 86400 }
  ]
}

```

* **Примечание:** Передавать можно только те параметры, которые нужно изменить. Если нужно удалить все искусственные отказы, передайте `"failures_update": []`.

### 3.3. Аналитика

**`GET /api/analysis`**
Выполняет полную суточную симуляцию.

* **Возвращает:** Доступность в процентах (`availability_pct`), максимальный перерыв связи (`max_break_s`), историю обрывов с указанием причин (например, `NO_VISIBLE_SATELLITE` или `BROKEN_ISL_NETWORK`).

### 3.4. Сохранение и сравнение (Папка saved_variants)

При перезапуске сервера оперативная память очищается. Для защиты эталонных расчетов используется файловая система.

* **`POST /api/save-variant/{name}`**: Физически записывает текущую конфигурацию в файл `saved_variants/{name}.json`.
* **`GET /api/compare/{name1}/{name2}`**: Автоматически загружает два сценария с диска, проводит для них раздельные симуляции и выводит разницу в метриках (насколько выросла или упала доступность связи).

### 3.5. Экспорт отчетов

Группа методов **`/api/export...`** генерирует полные логи симуляции и отдает их с заголовком `Content-Disposition`. Это вызывает системное окно загрузки в браузере, позволяя сохранить готовый JSON-отчет прямо на компьютер.

## 4. Дополнительные задачи

**`GET /api/robustness`** (Доп. задача 5)
Определяет критичность каждого спутника. Алгоритм по одному выводит из строя активные аппараты и замеряет падение метрики `min_availability_pct` у наземных клиентов. Возвращает отсортированный топ самых уязвимых узлов.

**`GET /api/auto-tune`** (Доп. задача 6)
Автоматически оптимизирует параметры `raan_deg` (долгота восходящего узла) и `phase_deg` (фазовый сдвиг).

* Сначала генерирует N случайных точек в пространстве решений.
* Выбирает лучшие из них и запускает алгоритм локального уточнения (с шагами от грубого к точному).
* Возвращает идеальную конфигурацию и процент улучшения (`improvement_over_baseline_pct`) по сравнению с исходным сценарием.
