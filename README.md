# CosmoSats Advanced Production API

Вычислительный бэкенд для моделирования, анализа и оптимизации спутниковых группировок. Разработан в рамках проекта КосмоХакатон 2026.

Система позволяет загружать параметры орбитальных группировок, симулировать их движение в течение суток, строить динамические маршруты связи и проверять систему на устойчивость к отказам.

---

## 1. Архитектура и алгоритмы

Проект построен по модульному принципу. Каждый скрипт отвечает за строго определенную математическую или логическую задачу.

* **`main.py`** — Точка входа на базе FastAPI. Отвечает за маршрутизацию HTTP-запросов, валидацию JSON-схем, безопасное сохранение конфигураций на диск и навигацию по временной шкале[cite: 10].
* **`geometry.py`** — Баллистический калькулятор. Рассчитывает координаты спутников в инерциальной и вращающейся системах координат, вычисляет углы места и дальность между аппаратами[cite: 16].
* **`router.py`** — Маршрутизатор. Использует алгоритм поиска в ширину (**BFS**) для нахождения кратчайшего пути от клиентского терминала до шлюза[cite: 13].
* **`analyzer.py`** — Движок симуляции. Прогоняет расчеты по временной сетке, фиксирует разрывы связи и считает суммарную доступность сети[cite: 17].
* **`resilience.py`** — Модуль стресс-тестирования. Поочередно отключает активные спутники, чтобы составить рейтинг наиболее уязвимых узлов сети[cite: 14].
* **`optimization.py`** — Модуль автоподбора орбит. Комбинирует случайный поиск с локальным спуском для нахождения оптимальных углов наклона и фазирования[cite: 15].
* **`adapter.py`** — Вспомогательный слой для преобразования логов симуляции в метрики для модулей аналитики[cite: 18].

## 2. Установка и запуск

Для работы требуется Python 3.10+.

### Настройка для Linux (Ubuntu)
```bash
# Создание и активация виртуального окружения
python3 -m venv venv
source venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt

# Запуск сервера
uvicorn main:app --reload --port 8000

```

Документация и панель управления (Swagger) доступны по адресу: **http://127.0.0.1:8000/docs**

## 3. Справочник API и рабочий процесс

### 3.1. Инициализация и навигация по времени

* **`POST /api/load`**: Загружает стартовый сценарий формата `cosmo-A-1.0`. Без этого шага система работать не будет.


* **`GET /api/snapshot/{t_s}`**: Возвращает геометрию сети (координаты, видимость, маршруты) в конкретную секунду `t_s`.


* **`GET /api/snapshot/step/{current_t_s}/{direction}`**: Эндпоинт для кнопок "Вперед/Назад" на фронтенде. Принимает текущее время и направление (`next` или `prev`). Автоматически сдвигает время на шаг симуляции, не выходит за границы суток и возвращает флаги `is_start` / `is_end` для блокировки кнопок интерфейса.



### 3.2. Горячее редактирование и быстрое сохранение

**`POST /api/update-config`**
Позволяет точечно менять параметры активного сценария. Если передать ключ `save_as`, сервер мгновенно сохранит обновленный вариант на жесткий диск.

* **Формат запроса:**

```json
{
  "launch_stage": 3,
  "isl_range_km": 2000.0,
  "planes_update": [
    { "id": "P1", "raan_deg": 15.0, "phase_deg": 0.0 }
  ],
  "failures_update": [],
  "save_as": "my_new_variant"
}

```

* **Примечание:** Передавать можно только те параметры, которые нужно изменить. Передача `"failures_update": []` удалит все искусственные поломки.



### 3.3. Аналитика

**`GET /api/analysis`**
Выполняет полную суточную симуляцию. Возвращает доступность в процентах, максимальный перерыв связи и историю обрывов с указанием причин.

### 3.4. Сохранение и сравнение (Папка saved_variants)

При перезапуске сервера оперативная память очищается, эталоны хранятся в файловой системе.

* **`POST /api/save-variant/{name}`**: Самостоятельный метод для физической записи конфигурации в файл `saved_variants/{name}.json`.


* **`GET /api/compare/{name1}/{name2}`**: Автоматически загружает два сценария с диска, проводит для них раздельные симуляции и выводит разницу в метриках.



### 3.5. Экспорт отчетов

Группа методов **`/api/export...`** генерирует полные логи симуляции и отдает их с заголовком `Content-Disposition`. Это вызывает системное окно загрузки в браузере, позволяя сохранить готовый JSON-отчет прямо на компьютер.

## 4. Дополнительные задачи

**`GET /api/robustness`** (Доп. задача 5)
Определяет критичность каждого спутника. Выводит из строя активные аппараты по одному и замеряет падение метрики `min_availability_pct` у наземных клиентов.

**`GET /api/auto-tune`** (Доп. задача 6)
Автоматически оптимизирует параметры `raan_deg` и `phase_deg`. Возвращает идеальную конфигурацию и процент улучшения (`improvement_over_baseline_pct`) по сравнению с исходным сценарием.
